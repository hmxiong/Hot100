Reduce 可视化：warp shuffle → shared memory → warp0 二次归约 → atomicAdd

这是对 reduce.cu 中 recude_v3 的抽象可视化：展示一个 block 内线程如何通过 __shfl_down_sync 做 warp 归约、lane0 写入 shared、warp0 读取 shared 再归约，最后对全局输出做 atomicAdd。硬件层面（例如 5090）实际的 SM 数量、调度、吞吐由架构决定，这里用“warp/SM/内存层次”做可交互的近似解释。

配置

已对齐 可视化现在按你修正后的 kernel：真实 warp（32 lanes）+ __activemask() + shared 写后 __syncthreads() + warp0 分批读取 shared 做二次归约。
提示 如果设置的 BLOCK_SIZE 不是 32 的倍数，会出现“尾部 partial warp”，页面会用 active mask 的逻辑展示它如何避免读到无效 lane 的数据。
